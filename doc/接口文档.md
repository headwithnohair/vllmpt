> 版本：v1.0（2026-10-26）
> 范围：全项目 12 个 Controller 的 HTTP / SSE 接口契约。
> 配套文档：[需求文档.md](./需求文档.md)、[审批业务链路说明.md](./审批业务链路说明.md)。

## 0. 通用约定

### 0.1 服务地址

| 环境 | Base URL |
|---|---|
| 本地默认 | `http://localhost:8080` |
| Swagger UI | `http://localhost:8080/swagger-ui.html` |
| OpenAPI JSON | `http://localhost:8080/v3/api-docs` |

### 0.2 统一响应体

除 SSE 与个别返回 `Map` 的接口外，均返回：

```json
{ "code": 200, "message": "Success", "data": null }
```

- `code`：业务码；`200` 表示成功；
- `message`：提示文案；
- `data`：业务数据。

> 业务异常与参数校验异常由 `GlobalExceptionHandler` 捕获后**仍以 HTTP 200 返回**，错误信息体现在 `code` / `message` 中。客户端必须判断 `code`，不能只看 HTTP 状态。

### 0.3 身份

- 请求头 `X-User-Id: {userId}` 指定当前用户；
- 开发环境（`app.identity.default-user-enabled=true`）不传时默认用户 `1`；
- 生产环境必须关闭默认用户并接入真实登录态；
- 当前 `WebSecurityConfig` 的公开路径包含 `/**`，即实际全部放行，身份完全依赖请求头，禁止直接暴露公网。

### 0.4 业务码

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数缺失 / 格式错误 / 状态不允许 |
| 402 | 今日 Token 额度已用完 |
| 403 | 无权操作 / 无权查看 |
| 404 | 资源不存在 |
| 409 | 状态已变化 / 会话处理中 / 任务已处理 |
| 429 | 并发请求过多 / 审批处理中 |
| 500 | 内部异常 / 业务校验失败 |
| 505 | 流水线中断（请求体为空、未产生响应等） |

### 0.5 列表参数

审批与文件列表的 `limit` 默认值不同，但都会在服务端钳制到 `[1, 100]`。

### 0.6 SSE 约定

| 帧 | 含义 |
|---|---|
| 文本帧 | 模型增量输出 |
| `[DONE]` | 正常结束，客户端关闭连接 |
| `[ERROR] {message}` | 流内错误（会话占用、流水线未产生响应等） |
| `[CANCELLED]` | 用户主动取消（S3 实现后启用） |

> SSE 接口在建立流之前抛出的异常（如 429 并发超额）仍以 JSON 形式返回。

## 1. 对话与 AI 能力

### 1.1 同步 Pipeline 对话

```
POST /api/pipline/fack
Content-Type: application/json
```

请求体 `MultimodalChatRequest`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionId` | String | 否 | 会话 ID，用于记忆与互斥锁；为空时跳过会话锁 |
| `userId` | String | 否 | 用户标识，用于并发限制与 Token 配额；为空时退回 `sessionId`，再兜底 `anonymous` |
| `bizType` | String | 否 | 审批业务类型（如 `LEAVE`）；有值时进入审批填表场景 |
| `text` | String | 是 | 用户输入 |
| `attachments` | Attachment[] | 否 | 附件列表 |
| `modelName` | String | 否 | 指定模型，为空用默认 |
| `temperature` | Double | 否 | 温度 |
| `maxTokens` | Integer | 否 | 最大 Token |
| `isStream` | Boolean | 否 | 流式标记（本接口固定同步） |

`Attachment`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | String | `image` / `video` / `audio` / `pdf` / `doc` / `txt` |
| `url` | String | MinIO 临时 URL 或 fileId |
| `name` | String | 原文件名（可选） |

响应：`Result<String>`，`data` 为模型回复文本。

主要错误：

| code | 场景 |
|---|---|
| 402 | 今日 Token 额度不足（预扣失败） |
| 429 | 单用户并发超限 |
| 409 | 同一 `sessionId` 正在处理中 |
| 505 | 请求体为空、流水线中断或未产生响应 |

> 执行顺序：并发额度 → Token 预扣 → 会话锁 → Pipeline。预扣失败会先释放并发额度。

### 1.2 SSE 流式 Pipeline 对话

```
POST /api/pipline/stream
Content-Type: application/json
Accept: text/event-stream
```

请求体同 1.1。

响应：`text/event-stream`，逐 token 推送，结束推 `[DONE]`。

- 并发超额：建立流之前抛 429，返回 JSON；
- 会话占用：流内推 `[ERROR] 该会话正在处理中，请稍候再试`，随后 `[DONE]`；
- 流水线中断：推 `[ERROR] {reason}` + `[DONE]`；
- 未产生响应：推 `[ERROR] 流水线未产生响应` + `[DONE]`。

### 1.3 多文件多模态对话（同步）

```
POST /api/chat/multimodal/multiple
Content-Type: application/json
```

请求体同 `MultimodalChatRequest`。`attachments` 必填，否则返回 `code=500`「Attachments required」。

响应：`{ "response": "..." }`（非 `Result` 包装）。

### 1.4 多文件多模态对话（SSE）

```
POST /api/chat/multimodal/stream
Content-Type: application/json
Accept: text/event-stream
```

请求体同上。响应：`text/event-stream`，结束推 `[DONE]`。

### 1.5 快捷回复（占位）

```
POST /api/chat/multimodal/easyReply
Content-Type: application/json
```

请求体同上；`attachments` 必填。当前实现固定返回 `{ "response": "" }`，为占位接口。

### 1.6 上传图片并对话

```
POST /api/chat/multimodal/upload-and-chat
Content-Type: multipart/form-data
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionId` | String | 是 | 会话 ID |
| `file` | File | 是 | 图片，仅 `image/*`，≤10MB |
| `text` | String | 是 | 对话文本 |

响应：

```json
{ "response": "", "imageUrl": "http://..." }
```

> 当前仅完成图片上传，`response` 固定为空字符串（对话调用被注释）。

### 1.7 混合检索

```
POST /api/hybrid/search?topK=5
Content-Type: text/plain
Body: 查询词（raw text，不是 JSON 对象）
```

| 参数 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `query` | body | - | 查询词，不能为空（空返回 400） |
| `topK` | query | 5 | 返回条数 |

响应：`Result<List<String>>`，按 RRF 分数降序的分块文本。

> 当前 `bm25Search` / `rrfFuse` 仍为 TODO，调用会返回 `code=500`（`UnsupportedOperationException`），属预期现象。

### 1.8 审批填表对话（P2）

审批填表复用对话接口，不新增 HTTP 路径；请求体增加 `bizType` 即进入审批场景：

```
POST /api/pipline/fack 或 /api/pipline/stream
Content-Type: application/json
X-User-Id: 1

{
  "sessionId": "s-approval-1",
  "bizType": "LEAVE",
  "text": "下周二到周三请年假，回老家"
}
```

服务端行为：

1. 系统提示词切换为 `ApprovalPromptBuilder.build(bizType)`，注入最新已发布模板的 `form_schema`；
2. 只暴露 `approval` 工具组（`ApprovalToolProvider`），不暴露天气/通用工具；
3. 跳过知识库检索；
4. 通过 `ToolContext` 注入 `userId / sessionId / bizType`，工具方法不接受这三个参数；
5. 用户身份取 `X-User-Id`，生产环境缺失时工具调用返回 401。

可用工具（模型自动调用，非 HTTP 接口）：

| 工具 | 参数 | 行为 |
|---|---|---|
| `saveApprovalDraft` | `formJson` | 合并草稿，返回 `missingFields` 与当前表单 |
| `submitApprovalDraft` | 无 | 提交草稿，返回实例 ID / 单号 / 当前节点 |
| `queryMyApprovals` | `status`（可选） | 查询本人该业务类型的审批记录 |
| `cancelApproval` | `instanceId` | 撤回本人运行中的审批 |

错误表现：

- `bizType` 没有已发布模板：`/fack` 返回 `code=505`，`/stream` 推 `[ERROR]` 帧；
- 草稿不完整时 `submitApprovalDraft` 返回工具错误文本，模型应继续追问；
- 非法 `formJson` 返回工具错误文本「formJson 必须是合法的 JSON 对象」。

## 2. 文件与知识库

### 2.1 获取预签名直传地址

```
POST /api/file/upload/UploadUrl
Content-Type: application/json

{ "fileName": "report.pdf" }
```

响应：

```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "objectName": "uuid_report.pdf",
    "presignedUrl": "http://..."
  }
}
```

- 桶：`vllmpt-temp`；
- 方法：`PUT`；
- 有效期：5 分钟；
- `objectName` 为后续提交任务/入库接口的必填参数。

### 2.2 上传图片（Multipart）

```
POST /api/file/upload/image
Content-Type: multipart/form-data

file: <图片文件>
```

- 仅 `image/*`，≤10MB；
- 响应：`{ "url": "http://..." }`；
- 非图片或超限抛 `IllegalArgumentException`，经全局兜底返回 `code=500`。

### 2.3 从 URL 转存图片

```
POST /api/file/upload/from-url
Content-Type: application/json

{ "imageUrl": "https://..." }
```

响应：`{ "url": "http://..." }`。

### 2.4 提交异步解析任务（大文件主入口）

```
POST /api/file/task/submit
Content-Type: application/json
```

请求体 `FileSubmitRequest`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `objectName` | String | 是 | `vllmpt-temp` 桶中的对象名 |
| `fileName` | String | 否 | 原始文件名，缺省取 `objectName` |
| `etag` | String | 否 | PUT 响应头中的 ETag，带上则做一致性校验 |
| `userId` | Long | 否 | 用户 ID，0/空表示未登录/系统任务 |

响应：`Result<String>`，`data` 为 `taskId`。

服务端同步动作：校验 temp 文件 → 归档到 `vllmpt-data` → 建台账 → 发解析消息 + 超时检查延迟消息。之后全部异步。

主要错误：

| code | 场景 |
|---|---|
| 400 | `objectName` 为空 / 文件不存在或未完成上传 / ETag 不一致 |
| 500 | 归档失败 / 消息发送失败（台账会标记失败） |

### 2.5 任务详情

```
GET /api/file/task/{taskId}
```

响应：`Result<FileParseTask>`；不存在返回 404。

### 2.6 最近任务列表

```
GET /api/file/task/list?userId=123&limit=20
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `userId` | 否 | - | 不传返回全部（dev 联调） |
| `limit` | 否 | 20 | 钳制到 `[1,100]` |

响应：`Result<List<FileParseTask>>`。

### 2.7 同步文件入库（旧链路）

```
POST /api/indexAction/file
Content-Type: application/json
```

请求体 `FileUploadDTO`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `objectName` | String | temp 桶对象名 |
| `fileSize` | long | 文件大小（服务端会回填） |
| `mimeType` | String | MIME 类型（服务端会回填） |
| `businessId` | String | 业务关联 ID（可选） |
| `etag` | String | 校验用（可选） |

响应：`Result<String>`，`data` 为归档后的 `finalObjectName`。

> 同步执行「校验 → 跨桶归档 → 解析 → 向量化」，大文件请改用 2.4。

### 2.8 对象存储文件流式处理

```

{ "objectName": "..." }
```

无响应体（`void`）。内部执行磁盘空间检查与并发限流（信号量 4）。

```

Content-Type: text/plain
```

无响应体（`void`），结果仅体现在向量库。

### 2.10 语义检索（调试）

```
Content-Type: text/plain
Body: 查询词
```

无响应体（`void`），命中结果输出到日志（Top-3，minScore=0.7）。

## 3. 审批平台

前缀：`/api/approval`。身份通过 `X-User-Id` 传递。

### 3.1 模板

#### 3.1.1 创建草稿模板

```
POST /api/approval/template
Content-Type: application/json
```

请求体 `TemplateCreateRequest`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `templateKey` | String | 是 | 模板键，如 `leave`、`travel_expense` |
| `bizType` | String | 是 | 业务类型 |
| `name` | String | 是 | 模板名称 |
| `description` | String | 否 | 描述 |
| `formSchema` | Object | 是 | 表单字段定义 |
| `aiFillEnabled` | Boolean | 否 | 是否启用 AI 填表 |
| `nodes` | TemplateNodeRequest[] | 是 | 节点列表 |

`TemplateNodeRequest`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `nodeKey` | String | 模板内唯一 |
| `nodeName` | String | 节点名称 |
| `nodeType` | String | `START/APPROVAL/AI_DECISION/CC/CONDITION/END` |
| `sortOrder` | Integer | 不传按数组顺序 |
| `assigneeType` | String | `USER/ROLE/DIRECT_MANAGER/DEPT_HEAD/FORM_FIELD/INITIATOR` |
| `assigneeConfig` | Object | 审批人配置，如 `{"roleCode":"HR"}` |
| `approvalMode` | String | `ANY/ALL/SEQUENTIAL` |
| `conditionJson` | Object | 跳过条件 |
| `aiPolicyKey` | String | AI 策略键 |
| `aiMinConfidence` | Decimal | 自动通过最低置信度 |
| `aiOnApproveNodeKey` | String | AI 通过跳转节点 |
| `aiOnEscalateNodeKey` | String | AI 转人工节点 |
| `aiOnRejectAction` | String | `REJECT/NEXT_NODE` |
| `ccConfig` | Object[] | 抄送配置 |
| `slaHours` | Integer | 超时小时数 |
| `enabled` | Boolean | 是否启用 |

响应：`Result<Long>`，`data` 为模板 ID。

错误：400（同一 `templateKey` 已有草稿、`nodeKey`/`sortOrder` 重复、节点类型/审批人类型/模式非法）。

#### 3.1.2 编辑草稿模板

```
PUT /api/approval/template/{id}
```

请求体 `TemplateUpdateRequest`：`name`、`description`、`formSchema`、`aiFillEnabled`、`nodes`（全量替换）。

- 仅 `DRAFT` 可编辑，否则 400；
- `aiFillEnabled` 为空时保留原值；
- 响应：`Result<Void>`。

#### 3.1.3 发布模板

```
POST /api/approval/template/{id}/publish
```

校验：必须且只能有一个 `START`、至少一个 `END`；审批节点必须有 `assigneeType` 与对应配置；`ROLE/USER/FORM_FIELD` 配置必须合法；不支持的类型/模式报 400。

响应：`Result<Void>`。

#### 3.1.4 下线模板

```
POST /api/approval/template/{id}/disable
```

- 仅 `PUBLISHED → DISABLED`；
- 运行中实例固定 `template_id`，不受影响；
- 响应：`Result<Void>`。

#### 3.1.5 模板详情

```
GET /api/approval/template/{id}
```

响应：`Result<TemplateDetailVO>`：

```json
{
  "template": { "id":1, "templateKey":"leave", "bizType":"LEAVE", "name":"请假审批",
                "version":1, "status":"PUBLISHED", "formSchema":"{...}",
                "aiFillEnabled":1, "createdBy":1 },
  "nodes": [ { "nodeKey":"start", "nodeType":"START", "sortOrder":0 } ]
}
```

不存在返回 404。

#### 3.1.6 模板列表

```
GET /api/approval/template/list?bizType=LEAVE
```

`bizType` 可选。响应：`Result<List<ApprovalTemplate>>`。

#### 3.1.7 按业务类型获取表单 Schema

```
GET /api/approval/template/schema/{bizType}
```

响应：`Result<String>`，`data` 为最新已发布模板 `form_schema` 的 JSON 字符串，客户端需二次解析。

不存在返回 404「未找到已发布的审批模板」。

### 3.2 实例

#### 3.2.1 提交审批

```
POST /api/approval/instance/submit
Content-Type: application/json
```

请求体 `SubmitInstanceRequest`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `templateKey` | String | 二选一 | 优先按模板键找最新已发布版本 |
| `bizType` | String | 二选一 | `templateKey` 为空时按业务类型找 |
| `title` | String | 否 | 标题 |
| `formData` | Object | 是 | 表单数据，按 `form_schema` 校验 |
| `facts` | Object | 否 | 显式事实，覆盖同名表单字段 |
| `idempotencyKey` | String | 否 | 提交幂等键（建议 UUID），5 分钟内重复返回同一实例 |

响应：`Result<Long>`，`data` 为实例 ID。

行为：

- 幂等：首次写 `PENDING`；已完成返回原实例 ID；处理中返回 429；
- 事实集 = 表单字段 + 显式 `facts` + `applicantId` + `bizType`；
- 实例号：`AP + yyyyMMdd + 6 位序号`；
- 提交、流水、引擎启动在同一事务内。

主要错误：

| code | 场景 |
|---|---|
| 400 | `templateKey` 与 `bizType` 同时为空 / 表单校验失败 |
| 404 | 未找到已发布模板 |
| 429 | 相同幂等键正在处理中 |

#### 3.2.2 实例详情

```
GET /api/approval/instance/{id}
```

响应：`Result<InstanceDetailVO>`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `instance` | ApprovalInstance | 实例主体 |
| `templateName` | String | 模板名称 |
| `tasks` | ApprovalTask[] | 任务列表 |
| `records` | ApprovalRecord[] | 流水 |
| `ccs` | ApprovalCc[] | 抄送 |

可见性：申请人 / 该实例任务审批人 / 该实例抄送接收人，否则 403；不存在 404。

#### 3.2.3 我的申请

```
GET /api/approval/instance/my?status=RUNNING&limit=20
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `status` | 否 | - | `RUNNING/APPROVED/REJECTED/CANCELED/TERMINATED` |
| `limit` | 否 | 20 | 钳制 `[1,100]` |

响应：`Result<List<ApprovalInstance>>`，按创建时间倒序。

#### 3.2.4 撤回

```
POST /api/approval/instance/{id}/cancel
Content-Type: application/json

{ "reason": "不再需要" }
```

- 仅申请人、仅 `RUNNING`；
- 实例置 `CANCELED`，所有 `PENDING/WAITING` 任务置 `CANCELED`；
- 写 `WITHDRAW` 流水；
- 响应：`Result<Void>`。

错误：403（非申请人）、400（非运行中）、409（并发状态变化）。

#### 3.2.5 驳回后重新提交

```
POST /api/approval/instance/{id}/resubmit
Content-Type: application/json

{
  "formData": { "...": "可选，修改后的表单" },
  "facts": { "...": "可选" },
  "title": "可选",
  "idempotencyKey": "可选"
}
```

规则：

1. 仅申请人、父实例必须 `REJECTED`；
2. 沿用父实例 `template_id` 与版本，不自动切新版本；
3. 新建实例，`parent_instance_id` 指向旧实例，`submit_count = 父实例 + 1`；
4. `formData` 为空时沿用父实例表单快照，仍重新做 Schema 校验；
5. 写 `RESUBMIT` 流水，备注原实例号；
6. 模板已 `DISABLED` 时禁止重新提交。

响应：`Result<Long>`，新实例 ID。

### 3.3 任务

#### 3.3.4 拒绝


- 实例置 `REJECTED`，写 `finished_at`；
- 响应：`Result<Void>`。

#### 审批模式行为

| 模式 | 同意 | 拒绝 |
|---|---|---|
| `ANY` | 一人通过即推进，其余任务取消 | 一人拒绝即实例拒绝 |
| `ALL` | 全部通过才推进 | 任一拒绝即实例拒绝 |
| `SEQUENTIAL` | 激活下一个 `WAITING`；最后一个通过后推进 | 任一拒绝即实例拒绝 |

### 3.5 填表草稿

```
POST /api/approval/draft

{
  "bizType": "LEAVE",

  "formData": { "leaveType": "ANNUAL", "startTime": "2026-10-27 09:00" }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `bizType` | String | 是 | 业务类型，需存在已发布模板 |

```json
  "updatedAt": "2026-10-26 21:30:00"
}
```

错误：400（参数）、404（无已发布模板）；Redis 不可用时保存降级（返回结果但不落库）。

### 3.6 请假业务

> 请假是审批平台第一个业务插件（`LeaveBizHandler`），通用提交仍需经过模板、幂等、引擎；业务规则（工作日、余额、时间重叠）在插件内完成。

#### 3.6.1 提交请假

```
POST /api/leave/request
Content-Type: application/json

{
  "leaveType": "ANNUAL",
  "startTime": "2026-10-27 09:00",
  "endTime": "2026-10-28 18:00",
  "reason": "回老家",
  "attachmentUrls": [],
  "title": "请假申请",
  "idempotencyKey": "uuid"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `leaveType` | String | 是 | `ANNUAL/SICK/PERSONAL/COMP_TIME` |
| `startTime` | String | 是 | `yyyy-MM-dd HH:mm` |
| `endTime` | String | 是 | `yyyy-MM-dd HH:mm` |
| `reason` | String | 是 | ≤500 字 |
| `attachmentUrls` | String[] | 否 | 病假超过 1 天必传 |
| `title` | String | 否 | 缺省「请假申请」 |
| `idempotencyKey` | String | 否 | 提交幂等键 |

响应：`Result<Long>`，`data` 为审批实例 ID。

业务规则：

- 结束时间必须晚于开始时间，不能请过去的假，暂不支持跨年；
- 天数由服务端按工作日计算，支持半天（开始 ≥13:00 或结束 ≤12:00 计 0.5）；
- 年假/调休校验并锁定余额，病假/事假不占用余额；
- 病假超过 1 天必须有证明材料；
- 与本人 `RUNNING/APPROVED` 的请假时间重叠则拒绝。

#### 3.6.2 请假详情

```
GET /api/leave/request/{instanceId}
```

响应：`Result<LeaveDetailVO>`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `approval` | InstanceDetailVO | 审批实例 + 任务 + 流水 + 抄送 |
| `leave` | LeaveRequest | 请假业务数据 |

#### 3.6.3 我的请假

```
GET /api/leave/request/my?status=RUNNING&limit=20
```

响应：`Result<List<ApprovalInstance>>`，仅返回 `bizType=LEAVE` 的本人申请。

#### 3.6.4 撤回请假

```
POST /api/leave/request/{instanceId}/cancel

{ "reason": "不再需要" }
```

响应：`Result<Void>`；撤回后释放已锁定的假期余额。

#### 3.6.5 假期余额

```
GET /api/leave/balance
```

响应：`Result<List<LeaveBalance>>`，当前用户当年年假/调休余额，含 `totalDays/usedDays/lockedDays`。
